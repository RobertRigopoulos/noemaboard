# Noema desktop app

The desktop app is a thin, hardened Electron shell around the same web app that is deployed to
GitHub Pages. Everything a user creates stays on their computer and syncs peer-to-peer.

## Develop

```sh
npm install            # also downloads the Electron binary (postinstall: install-electron)
npm run dev:desktop    # electron-vite dev: renderer with hot reload on http://localhost:5174
npm run build:desktop  # bundles main, preload and renderer into out/
npm run preview:desktop
```

Packaging (output in `release/`):

```sh
npm run dist:win    # NSIS installer + portable .exe
npm run dist:mac    # dmg + zip (x64 and arm64), ad-hoc signed
npm run dist:linux  # AppImage + deb
```

electron-builder writes auto-update metadata for the GitHub repository it finds in the git remote
(`origin`). In a folder that is not a GitHub clone, pass it explicitly, e.g.
`npx electron-builder --win --publish never --config.publish.owner=<owner> --config.publish.repo=<repo>`.

Headless self-check of a packaged build (prints one JSON line, exit code 0 = healthy):

```sh
release/win-unpacked/Noema.exe --smoke-test
# also exercise a real link preview + image download through IPC:
NOEMA_SMOKE_NETWORK=1 release/win-unpacked/Noema.exe --smoke-test
```

The smoke test uses a throwaway profile in the temp folder, so it never touches real boards and
can run while the app is open.

## Layout

| File | Purpose |
| --- | --- |
| `main.ts` | App lifecycle, single instance, deep links, window, tray, menu, updates |
| `preload.ts` | `window.desktop` (contract: `src/lib/desktop.ts`), sandboxed, CommonJS |
| `appProtocol.ts`, `bundle.ts` | Serves the renderer from `app://bundle/` with a strict CSP |
| `ipc.ts`, `validate.ts` | IPC handlers; every call checks the sender frame and its arguments |
| `linkPreview.ts`, `netGuard.ts`, `htmlMeta.ts` | SSRF-guarded link previews and preview images |
| `deeplink.ts` | `noema://` invite links (argv, macOS `open-url`, queue until the UI listens) |
| `tray.ts`, `autostart.ts`, `settings.ts` | Optional "keep boards online" tray mode and open-at-login |
| `window.ts`, `windowState.ts` | Hardened `BrowserWindow`, remembered size/position, mouse back/forward buttons |
| `contextMenu.ts` | Native menu for text fields, selections, links and images the page leaves alone (Copy image) |
| `updater.ts` | electron-updater (Windows installer and Linux AppImage) |
| `smoke.ts` | `--smoke-test` |
| `icons.ts` | Generated by `npm run icons` (`build/make-icons.cjs`) from `public/icon.svg` |

## Things that must never change

`appId` (`org.noema.app`), `productName` (`Noema`) and the renderer origin
`app://bundle` decide where boards are stored (userData folder and IndexedDB origin). Changing any
of them makes existing boards invisible to the app.

## Security model

- Renderer: `sandbox`, `contextIsolation`, no Node integration, `webSecurity`, no `<webview>`.
- Content Security Policy is sent with every `app://` response (see `bundle.ts`).
- Navigation is limited to `app://bundle/` (and the dev server in development). Links open in the
  default browser (http, https and mailto only, rate-limited).
- Permissions: clipboard write, notifications and persistent storage for the app itself;
  fullscreen for embedded players; everything else is denied.
- `printToPdf` only ever prints the calling page itself, one job at a time, and accepts nothing but
  a page size (A4, Letter, A3) and an orientation.
- Link previews run in the main process with no cookies or proxies. Every hop is validated and the
  socket's DNS lookup refuses private, loopback, link-local, CGNAT, multicast and other special
  ranges (IPv4 and IPv6), which also defeats DNS rebinding. Bodies are capped (1 MB HTML, 10 MB
  images) and SVG is never accepted.
- Electron fuses disable `ELECTRON_RUN_AS_NODE`, `NODE_OPTIONS` and `--inspect`, enforce asar
  integrity and only load the app from the asar.

## Releases

1. Bump `version` in `package.json`, commit, tag `vX.Y.Z`, push the tag.
2. `.github/workflows/release.yml` builds all platforms and publishes the GitHub Release.
3. Installed Windows apps and Linux AppImages update themselves from GitHub Releases. The portable
   Windows build, the `.deb` and macOS builds (unsigned) are updated by downloading a new release.

Desktop builds create web invite links pointing at
`https://<owner>.github.io/<repo>/` unless the repository variable `PUBLIC_URL` is set.
